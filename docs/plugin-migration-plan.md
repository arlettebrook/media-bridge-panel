# 插件化改造：施工批次计划

- 状态：**计划**（随进度更新；改完的批次在这里打勾并记下验证方式）
- 依据：[plugin-contract.md](plugin-contract.md)（契约）· [adr/0028](adr/0028-plugin-system.md)~[0034](adr/0034-fresh-install-no-migration.md)（决策）
- 讨论存档：[plugin-arch-draft.md](plugin-arch-draft.md)

## 一、两条总原则

1. **批次是"开发与验证的顺序"，不是"发版顺序"。**
   按 [ADR-0034](adr/0034-fresh-install-no-migration.md)，本版当作全新安装、不留兼容分支 ——
   所以中间批次**不对外发版**，一次性把整套做完、发一个大版本。
   若改成"每批都发版"，就需要额外的兼容策略（与"不留兼容"相抵），不建议。
2. **能做成纯重构的批次，先做成纯重构**：外部行为一字不变，用"改动前后同一批请求的响应逐字对比"
   来证明没改坏。做不到"行为不变"的批次，要在计划里写明它变了什么、怎么验。

### 缓存落点（改造后各库归谁）

| 库 | 内容 | 归谁 | 位置 |
|---|---|---|---|
| `lines.db` | 这一条目的线路结果（面板聚合出来的那份） | 面板 | `cache/` |
| `sitestat.db` | 站点统计与测速（按插件 + 站点记账） | 面板 | `cache/` |
| 元数据响应缓存 + 名字索引 | 上游响应缓存、名字 → 搜索结果 | 元数据插件 | `plugins/metadata/tmdb/data/` |
| `image_index` | 图片索引 | emby 层（它服务的是图片端点） | `emby/cache.db`（不动） |
| 插件自己的取数缓存 | 各插件自己定 | 插件 | `plugins/<类型>/<id>/data/` |

### 这份树里已确认的四处

1. **内置插件随包发行**：仓库里 `plugins/` 放内置插件源码，开机同步进 `data/plugins/`
   —— 否则"全新安装"之后面板是空的（连元数据都没有）。先例：现在的内置首页示例就是这么同步的。
2. **`server/modules/source/` 并入 `server/modules/plugin/`**：
   它那套"下载包 / 起进程 / 端口 / 自动更新"现在要用在**所有插件**上，已经不是"源"专有。
3. **超时与并发进模板**；**测速的结果值是面板级共享的一份**（不跟模板走），
   **测速的开关与间隔放面板设置**。⇒ 于是原来「站点与参数」+「聚合参数」两页合成模板页，
   测速那两项挪去面板设置。
4. **图片索引留在 `emby/cache.db` 不动**（按 ADR-0011 的"按消费方分库"，
   它服务的是 emby 那侧的图片端点），不跟着元数据走。

## 三、通用验收口径（每批都要过）

- `npm run check`（文风 + 语法门禁）。
- **本机起实例**：`DATA_DIR=<临时目录> WEB_PORT=<端口> node server.js`，用浏览器逐页打开相关页面
  （前端改动必须真开一遍，不能只看代码）。
- **回归对比**：行为不变的批次，抓同一批端点（详情 / 季 / 集 / 图片 / 播放 / 首页）的响应，
  与改动前**逐字对比**。
- **路由器实测**：涉及部署形态的批次，按现有手法打进去、重启应用进程、验收后再决定去留。
- 每批完成后：把结果补记到本文对应小节，并同步受影响的文档。

### 批次 4 — 源插件化：整套搬进猫爪插件 · 已完成，待确认

**范围**（本批开工时定下的口径）：不只是把协议搬走，**连源实例本身一起搬** ——
猫爪插件自己存实例清单、自己下载与起实例进程、自己管自动更新与配置中心入口；
面板不再认识任何"源地址"。依据见 [plugin-contract.md](plugin-contract.md) 第十四节
与 [plugin-arch-draft.md](plugin-arch-draft.md) 第 82~83 行（"插件内部起几个实例、监听哪个端口，是插件自己的事"）。

**为什么一次搬完而不是分两步**：分两步会留一个"面板仍托管实例、只把协议转给插件"的过渡态，
那个过渡态里两套实例清单并存（面板的 `sources.json` + 插件的），反而更容易配错。
一次搬完，实例清单只有一个来源。

**做什么**

1. 新增 `plugins/source/catpaw/`：契约里那五个动作 + 自带 webui。
   包内自带取数所需的一切（HTTP 客户端、`/config` 摊平、下载器、实例进程管理、自动更新），
   **不 require 面板任何代码**（插件是独立包，面板升级不该牵着它）。
2. 面板删除源层：`server/modules/source/` 整个模块（下载 / 起进程 / 端口 / 自动更新 / 配置中心代理），
   `server/core/catpaw.js`（协议搬走；其中 `normName` 是**面板侧的打分知识**，归 `agg/match.js`），
   `/api/sources*`、`/api/run*`、`/api/base*`、`/website*` 与 `server.js` 的配置中心兜底转发。
3. 聚合层四处协议调用改成插件的动作：`/init`（并入插件的"候选"内）、`/search`、`/detail`、`/play`。
   新增 `agg/source-bridge.js` 作为唯一的转接处 —— 它把插件的回复**还原成上游那份形状**
   （`{ status, ok, text, json }`），所以 `service.js` 里那套 404=无结果、超时文案、逐站记账
   一个字都不动。这是本批"行为不变"的关键手法。
4. 站点清单的来源从"面板自己去问每个源的 `/config`"改成插件申报（本属批次 5，
   因为实例已经归插件、面板再也够不到那些地址，只能一起做）。

**行为变化（如实列出）**

| 变了什么 | 说明 |
|---|---|
| 源实例要重新加一遍 | 实例清单从 `data/sources.json` + `agg.sources` 挪进 `plugins/source/catpaw/data/`，按 [ADR-0034](adr/0034-fresh-install-no-migration.md) **不做数据迁移** |
| 「源托管」「配置中心」两页没了 | 收进插件的设置页（从「插件 → 管理 → 猫爪源 → 设置」进）；配置中心**直连实例端口**（面板不再在中间代理，原来的代理退成兜底也没了） |
| 「聚合设置 · 源列表」页没了 | 源与站点只在插件的设置页里管；站点与统计看「模板」页 |
| **少了"源起来就测一轮它的站点"** | 源实例现在活在插件里，面板收不到"它起来了"这件事（插件不反向通知面板）。开机那一轮（延迟 2 分钟）会覆盖自启的实例，想立刻看数字就点该站的「测速」 |
| 面板不再知道源地址 | 例外一处（见下"过渡态"） |

**过渡态（两处，写明理由，后面批次消掉）**

1. **端口**：`解析地址` 与 `取播放项` 目前仍要回给面板"这个实例的端口" ——
   `emby/service.js` 拼 302 地址时要拿它把回环地址换成客户端域名（见那个文件里 `rewritePlayUrl`）。
   彻底去掉要等批次 7（`ref` 转交）——那时插件直接给"客户端可直连的地址"。
2. **`站点清单` 仍带 `url` 字段**：只为诊断显示（"这个实例打的是哪个地址"），面板不再用它取数。

**动到**

- 新增：`plugins/source/catpaw/`（`plugin.json` / `index.js` / `lib/` / `ui/`）
- 新增：`server/modules/agg/source-bridge.js`（面板 ↔ 源插件唯一的转接处）
- 改：`agg/service.js`（四处协议调用）、`agg/api.js`（源与站点清单、单站测速）、
  `agg/match.js`（收下 `normName`）、`server.js`（去掉源模块与兜底）、`core/paths.js`（去掉源目录常量）
- 删：`server/modules/source/`、`server/core/catpaw.js`、`public/modules/source/`
- 前端改：`core/registry.js`（导航去掉「源托管」）、`core/boot.js`（不再读 `/api/sources`）、
  `app.js`、删 `modules/agg/host.js`（源列表页）

**验证（已做，全部实测）**

1. `npm run check` 通过（语法 + 文风）。
2. **本机起实例**（`DATA_DIR=/tmp/cp-t4 WEB_PORT=8199`，用一个**假的猫源**当被测对象：
   它实现了 `/check` `/config` `/init` `/search` `/detail` `/play`，还故意能回 404 与空列表）。
3. **装与托管**：装上并启用猫爪插件 → 加一个"本地部署"实例（插件下载源包 → 校验 md5 →
   起常驻进程 → 站点清单出来）→ 再加一个"外部地址"实例（同一个假源，不打进程）。
4. **取数四条路**：搜索（模板参数生效：`stats.timeoutMs = 8000`）、详情（两条线路、E1 定位到）、
   播放（拿到地址）、单站测速（回执里的源名来自插件）。**404 = 无结果** 与 **200 空列表**
   两条如实路径都验了（`noResultBy = http-404`）。
5. **站点身份**：面板侧是 `catpaw/s1`、`catpaw/s2`…（插件 id / 实例 id），
   两个实例有同名站点互不干扰。
6. **门禁**：插件 webui、它的转发通道、插件列表 —— 不带 cookie **全部 401**；路径穿越 **400**。
7. **换包不清数据**：改一下插件包再重启 → 日志报"已更新"，实例清单**原样还在**。
8. **停面板不留孤儿**：停掉面板 → 实例进程一并被带走（端口释放）。
9. **浏览器真开一遍**：导航只剩「聚合设置 / Emby / 插件 / 面板设置」；
   模板页站点表来自插件（4 个站、延迟列有数）、聚合搜索页真搜一次（2 站 / 4 条 · 10ms）、
   插件管理页显示猫爪源在跑、插件自己的设置页（实例表 + 增删启停更新 + 配置中心入口 + 自动更新）
   在 **1280px 与 390px** 下都验过（窄屏表格摊成卡片，无横向溢出）。
10. **一个源插件不实现 `站点清单` 时**：如实列成一行错误并点名它实现了哪些动作（拿「自检 · 回声」试的）。

**过程中发现并修掉的三处（都不在计划里，但都是真问题）**

1. **插件换包会把 `data/` 清空**（批次 3 留下的）：`installDir` 覆盖时先 `rmSync` 整个插件目录，
   `copyDir` 那句"跳过 data"只保证不复制、不保证不删 —— 实测把刚加好的实例清单清掉了。
   已改成"先把 `data/` 挪到一边、换完再挪回来"。
2. **宿主重启插件会有竞态**：`restart()` 只等 300ms 就 `start()`，而 `start()` 看到旧进程还在会直接返回
   —— 插件自己的善后逻辑越认真（退出越慢），越容易"停掉了却起不来"。已改成**等进程真的退出**再起。
3. **端口被抢会被误判成"起来了"**：两个实例配到同一个端口时，后起的那个的"端口通了"其实是前一个在答，
   于是顶着别人的站点装成自己（站点身份会张冠李戴）。已在 `host-boot` 里加了"启动前先看端口"，
   如实失败并说清原因。

**这一批没做（按计划留给后面）**：`解析地址` 收 `ref`（批次 7）、播放地址不再由面板改写（批次 7）、
缓存两级（批次 8）、`develop.md` 里的接口清单同步（批次 10 —— 那几个端点已经删了，
文档还写着它们，先在计划里挂账）。

**依赖**：批次 3（要有宿主才能调插件与托管 webui）。
**风险**：中高。这条链断了就是"搜不到、播不了" —— 所以用 `source-bridge.js` 把改动面收到最小，
并靠"逐字对比"来证明没改坏。

## 四之二、待定与挂账

开工前要先定、或明确留到某一批的事，都记在这里（别让它们散在对话里）。

1. **详情那条路的打分参数没跟模板走**（批次 2 留下的老问题）：`aggregateDetail` 内部那发搜索
   没有把 `params` 传下去，于是 `matchDefaults` 取的是**内置默认**（0.85 分 / 留 8 条），
   不是模板里填的值。影响面是 Emby 客户端那条链（它就是走 `aggregateDetail`）。
   修它很小（把 `params: cfg` 补上），**但会改行为**，所以先挂在这里等定夺。
2. **批次 7 要先定"线路与选集的解析归谁"**：契约第五节写的是"取播放项给每个播放项一个 `ref`"，
   听起来是**插件**解析 `$$$` / `#` / `$` 并产出播放项；而现在的分工是**面板**解析
   （`agg/service.js` 的 `parseLines` / `locateEpisode` / `parseEpisodeMeta`）。
   两种都说得通，但代价不同：
   · 搬进插件 —— 面板真的不再解析坐标（契约原意），但每个源插件都要**重新实现一遍**这套解析，
     万一实现得不一样，"同一个源换个插件"结果就不同；
   · 留在面板 —— 解析是**跨源共用的协议知识**（所有猫爪源共用 `$$$` 那套），面板编 `ref`
     再交给插件解释；代价是"面板不解析坐标"这句话打了折（它仍然知道 flag 与集 id）。
3. **批次 6（元数据插件化）的验证深度**：计划里要求"详情 / 季 / 集 / 图片 / 客户端搜索 / 首页
   全链回归"，那需要**真的 TMDB token**（本机数据目录里没有）。没有 token 只能验到结构面
   （插件注册域、按前缀分派、插件停掉后如实为空），回归得留到路由器上再补。
4. **`develop.md` 的接口清单**：`/api/sources* /api/run* /api/base* /website*` 与 `agg.json`
   那几项已经删了，文档还写着 —— 按计划归**批次 10**（模块清单 / API 契约 / 数据目录一起改一遍）。
