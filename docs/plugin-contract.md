# 插件契约

> **状态：已定稿，待实现。** 本文描述的是**目标形态**，当前代码尚未实现 ——
> 现在能配的仍然只有 `agg.json` 里那一套站点设置。实现进度以 `CHANGELOG.md` 为准。
> 决策依据见 [adr/](adr/) 的 0028~0034；讨论过程的存档见 [plugin-arch-draft.md](plugin-arch-draft.md)。

本文是插件契约的**唯一来源**：插件能做什么、面板会怎么调它、哪些必须遵守。代码里不放本文没写的字段或行为。

配套：[ARCHITECTURE.md](../ARCHITECTURE.md)（分层与依赖方向）、[develop.md](develop.md)（开发环境与实现要点）、
[emby-home-plugin.md](emby-home-plugin.md)（首页插件，本项目另一套独立的插件机制）。

---

## 一、定位与边界

| 角色 | 是什么 |
|---|---|
| **插件** | 一个可安装、可卸载的包，跑在自己的常驻子进程里，提供若干**动作** |
| **面板** | 宿主：安装校验、启停、把请求转成"对插件的动作调用"、把结果转成 Emby DTO 或页面数据 |
| **模板** | 一份配置数据文件（站点集合 + 打分过滤参数），按**域**被选用 |

**铁律（与项目既有取向一致）**

1. **不编数据**：插件给不了、或这次取失败，面板一律**如实留空并点名**，不猜、不静默。
2. **面板不解释插件的数据**：动作的入参出参由本文规定；插件内部怎么取数、怎么组织，面板不关心。
3. **不为未发布的东西留兼容**：契约、字段名、动作名该改就改，不留双读分支。

---

## 二、插件的身份与目录

- **类型**：`metadata`（元数据）、`source`（源）、`home`（首页插件）。
- **身份** = `(类型, 插件 id)`。同一个 `id` 在不同类型下是两个插件，互不冲突。
- **目录布局**（都在数据目录下）：

  ```
  plugins/<类型>/<插件 id>/          包本体（代码 + 自带 webui 静态文件 + 声明文件）
  plugins/<类型>/<插件 id>/data/     插件自己的数据目录（设置与缓存都在这里）
  ```

- **包**：一个 `tar.gz`。安装 = 解到 `plugins/<类型>/<id>/`。
  校验**复用现有的两道 md5**（与源包同一套，见 [ADR-0015](adr/0015-source-bundle-integrity.md)）。
  包里的清单声明 `version` 与"依赖的域 / 其他插件"；**缺依赖时如实失败并点名缺哪个**，不半启动。
- **插件的设置与缓存都由插件自己管**（都在它自己的 `data/` 下）。面板里的"清空插件数据"
  就是**删这个目录**。

---

## 三、执行模型

- 插件**跑在自己的常驻子进程**里，由面板启动与停止。
- **不沙箱**：插件能读写自己的目录、能联网、能起进程 —— 与"像 Linux 装包"同一个模型
  （权限前提与风险见 [ADR-0028](adr/0028-plugin-system.md)）。
- **"面板停、插件就停"由宿主保证**：子进程属于面板，面板退出时直接终止它们，不依赖插件配合。
- 插件**自己**再起的东西（例如源插件内部部署的实例）必须在收到停止指令时自行清理，
  否则会变成孤儿进程、继续占着端口。
- 面板要管 N 个进程（启停、健康、日志、崩溃重启）。这层复用现有源托管的做法
  （启动 / 嗅探端口 / 留尾部日志 / 停止）。

---

## 四、面板与插件之间的通道

- 走**管道**（Node 的 child IPC；非 Node 插件可用"stdin/stdout 每行一条 JSON"）。
  **不占端口**、**不用鉴权**（只有父子能碰）、更快。既有实现见首页插件的宿主
  （`job` / `rpc` / `rpcResult` / `done` 消息）。
- **动作名**：走管道之后没有"网址"，端点名就是**一个动作标识**。对比：

  ```
  现状：POST http://<源地址><站点 api>/search   { wd, page }
  之后：{ action: 'search', site: …, wd, page }
  ```

  动作名一律用**语义名**（`站点清单` / `搜索` / `取播放项` / `解析地址` / …），
  不写成 `/config`、`/search` 这类路径样式 —— 免得后来者以为还要发 HTTP。
- 插件**内部**要不要给自己的实例开端口，是插件自己的事；面板不参与分配、也不依赖它。
- 调试口径：面板把**每次请求与回复写进日志**（沿用现有源"留子进程尾部日志"的做法）。

## 五、源插件的动作

| 动作 | 入参 | 出参 | 必需性 |
|---|---|---|---|
| 站点清单 | — | 站点数组（含站点级能力申报） | 必需 |
| 候选 | 搜索词、页码 | 候选列表 | **仅两层式站点** |
| 取播放项 | 站点坐标（+ 搜索词） | 播放项列表，每项 = 面板地址 + `ref` | 必需 |
| 解析地址 | `ref` | 真实可直连地址 | 必需 |
| 站点测速 | — | 该站点的连通性与耗时 | 必需 |
| webui | — | 静态文件 | 可选 |

- **站点数可以是 0**。报 0 个站点的插件在站点表与模板里不出现（等于用不到它）——
  想让自己的插件被用就申报站点，这是插件作者的选择，面板不强制。
- **站点测速**同时回答"通不通"与"快不快"。不另设"探测"动作。
  ⇒ 分工是：**站点清单 = 静态声明有哪些站点；站点测速 = 实测能不能用、多快**。
- **播放项就是"线路"**：**一个名字对应一个地址**。两类站点都遵守这个结构，
  直查那类也**可以有多条**线路。差别只在"怎么取到这些线路"（见下：一层式 / 两层式）。

### 取数式样：一层式与两层式

**聚合的粒度是"版本"，不是"站点"**：对某一部片的某一集（一个元数据坐标），面板只做一件事 ——
向所有该域的站点询问"这一集有哪些可播线路"，能给出的各算一个版本，都不能给就如实空。

| 式样 | 链路 | 面板在中间做什么 | 适合 |
|---|---|---|---|
| **两层式** | 给词 → 候选列表 →（面板打分 / 过滤）→ 取播放项 | 打分与过滤 | 聚合站那类（返回的是候选，不挑就会拿错同名片） |
| **一层式** | 给词 → 直接回播放项列表 | 不做筛选（站点自己保证取准） | 直查那类（给关键词就出地址） |

**打分与过滤留在面板、不搬进插件**（理由见 [ADR-0033](adr/0033-template-and-domain.md) 的说明）：
它是**跨来源统一的判据**（`match.js` 是"这是不是目标作品"的唯一实现），搬进插件会让判据分叉。
其参数跟着**模板**走。

⚠️ 其中只有一部分参数对**一层式**站点有意义（它们不做筛选）⇒ 设置页要写清
"哪些参数只对两层式站点生效"，免得出现"调了没反应"。

## 六、元数据插件的动作

动作与"面板从上游元数据取用的东西"**一一对应**。

| 动作 | 入参 | 出参 | 必需性 |
|---|---|---|---|
| 注册 | — | 域 id + 能力清单 + 剧集式 / 电影式 | 必需 |
| 取元数据 | 条目坐标（一次一个） | 规范字段 + 成败 | 必需 |
| 取一季分集 | 条目坐标 + 季号 | 分集列表 | 必需 |
| 搜索 | 搜索词 | 候选列表 | 必需 |
| 首页内容 | 域 + 行 | 行 | 见第七节 |
| webui | — | 静态文件 | 可选 |

### "取元数据"要提供的字段（按用途分组）

- **身份**：条目 id、类型（电影 / 剧集）
- **名字与时间**：主标题、原始标题、年份、首播日期
- **给源站点搜索用的词**（现为 `searchTitle`：主标题没中文时回退中文别名）
- **简介**（面板按长度上限裁剪）
- **图片**：海报、背景，以及详情页用的图集
- **分类**：类型名列表 **与带 id 的类型项**（客户端要能点进"类型"，只给名字点不进去）
- **规模与评分**：季数、评分
- **详情页那一批**：标语、状态、时长、分级、制作公司（**必须带 id**）、制片国家、关键词、
  外部 id（imdb / tvdb / wikidata）、预告、演职、相似推荐

### "取一季分集"要提供的字段

集号、集名、简介、首播、剧照、评分、时长。**拿不到就如实留空**。

### 能力申报

`注册` 时申报**它会哪些、缺哪些**（即上面那两份字段清单 + 剧集式 / 电影式）。
面板按申报决定给客户端什么、缺的如实留空。

⚠️ **不属于插件、不要塞进来**：图片的**代取与签名**（面板为客户端取图，见
[ADR-0013](adr/0013-image-endpoint-signing.md)）、各类缓存（各自管各自的，见第十节）、
Emby 的 DTO 形状（面板负责转换，见 [ADR-0007](adr/0007-emby-dto-shape.md)）。

### 条目 Id

**形状由面板统一规定**，插件只提供"条目 id"（它自己的编号）+ 声明是剧集式还是电影式。
坐标的编解码**不下放给插件** —— 否则面板得懂每个域的坐标语法。
理由：条目 Id 与客户端、进度库的键、首页插件的条目契约绑在一起。

## 七、域、首页与分派

- 元数据插件注册一个**域 id**（就是条目 Id 的前缀，如 `tmdb`）。面板按域名把
  "条目 → 模板 → 站点"连起来。**面板层是元数据插件与源插件之间唯一的连接点**，
  两类插件互不感知。
- **分派**：条目前缀决定用哪个元数据插件。**认不出的前缀 ⇒ 如实空并点名缺哪个插件**
  （不回退到别的域、不猜、不静默）。
- **首页**：行的来源不强制 —— 首页插件**可以**去问元数据插件的"首页内容"动作，
  **也可以自定义去取**，只要按规范返回行即可。首页插件是编排者。

## 八、播放地址的转交

播放项里给客户端的地址是**面板的地址**（形如 `http://<面板域名>:<面板端口>/…/<ref>`）。
面板收到请求后通过管道把 `ref` 转给插件，插件回一个**真实可直连地址**，面板 **302** 过去
（面板不扛流量，见 [ADR-0006](adr/0006-redirect-for-playback.md)）。

- **host 必须是面板**：客户端要能访问那个地址，而面板的端口是已发布、确定可达的；
  插件自己的端口没有发布。客户端因此感知不到插件，也不需要知道插件在哪。
- **只做 302**：插件给不出"客户端可直连的地址"（例如必须带 header / cookie）时，
  面板**如实回"该源需要代理，暂不支持"**，不静默失败。
- **`ref` 由插件输出、插件自己管**：只要内容还在，插件随时能把它换成一个地址
  （可重复解析是**插件的义务**）；地址缓存与有效期也由插件自己处理。
- **播放项必须带一个显示名**（聚合站给线路名，直查那类自己决定：片名 / 集号 / 站点名都行）。
  **面板只负责把它传到客户端 —— 不起名、不编**；插件想不出名字就如实留空。

## 九、模板与域

- **模板就是一份配置数据文件**，内容 = **选中的站点 + 打分过滤参数 + 超时与并发**
  （超时与并发也按模板走：不同域的内容、不同的站点，合适的超时本来就不一样）；
  **它自己的 id 就是这套模板的身份**（随机生成、之后固定）。
- **每个域最多一个模板**（一对一）；**一个模板可以被多个域共用**；
  **同一个站点可以出现在多个模板里**（站点表要能看出"它被哪几套模板用了"）。
- 站点身份按 **"插件 + 站点 key"** 记，不用端口或实例名之类会变的东西 ——
  插件重装、换端口之后模板照样对得上。

## 十、缓存分工

**两级，各管一段。**

| 位置 | 缓存什么 | 有效期 | 谁决定 |
|---|---|---|---|
| **插件侧** | 它自己的取数结果 | 插件自己定 | 插件（面板不干预） |
| **面板侧** | **这一条目的线路结果**（面板聚合出来的那份） | **按天，默认 1 天**（可改） | 面板设置 |

- 面板侧那份的 `key` 里带上**所有影响结果的参数**（打分参数、线路过滤、模板、站点集合……）⇒
  **改了参数 key 就变、旧结果立即失效**，不需要人工清缓存。
- **判据是"只要有线路就存"**，不要求"所有站点都通"（见 [ADR-0032](adr/0032-cache-two-levels.md)）。
  代价如实记着：一次"缺了几条线路"的结果会在缓存里留最长一个有效期。
- **插件应当自己缓存，把常见查询做到秒回** —— 这是义务。面板侧那份只挡住
  "客户端点一次播放连问三遍"（几秒内），**超出的热度全压在插件身上**。
- 面板要**按插件记录每次聚合的耗时**（日志 + 统计），否则"慢插件"查不出来。
- 站点级超时与失败跳过按 **"插件 / 注册的站点"** 记账（沿用现有那套逻辑）。
- **测速的归属要分清**：**测速的结果值（站点统计）是面板级共享的一份**，不跟模板走；
  **测速的开关与间隔在面板设置里**。

## 十一、webui、设置与门禁

- 插件的 webui 是**静态文件**，放在插件包里、由面板托管；**插件不提供端口**。
- **导航**：插件注册了 webui 就在导航显示一个入口，"里面是什么"是插件自己的事；
  面板只判断"有没有注册 webui"。入口放在它**所属类型那一栏**下面
  （元数据插件挂「元数据」栏、源插件挂「源」栏）。
  入口是**扫插件目录里的声明文件**发现的（给显示名、排序、指向哪个页面），没有中心注册表 ——
  参照 LuCI 的做法（见第十三节）。
- **设置**：**声明归插件、存储也归插件**（都在插件自己的 `data/` 里）。
- **转发通道**：webui 是浏览器里的页面，只能发 HTTP ⇒ 它打到面板（同源），
  面板按路径里的"插件类型 + 插件 id"把请求**通过管道转给插件**。
  **面板不解析、不存储、不校验** —— 插件想怎么设计自己的接口都行。
- **门禁**：webui 的静态资源与上面那条转发通道**都必须受门禁**
  （当前静态文件是免登录的，不能让插件的设置页变成公开页面）。
- ⚠️ **两个层级要分开**：**插件设置页**属于插件（管理它自己的实例）；
  **实例配置中心**属于实例。导航**不再给每个运行中的实例单独开子页**，收进插件的设置页内部。

## 十二、失败与诊断

- **失败如实**：插件报失败，面板如实记日志、如实空；不编造、不静默回退。
- **可选诊断字段**：插件返回里可以带诊断信息（如"这次含预热""内部等了多久"），
  面板**照实写进日志，但不参与打分**。`init` 这类内部逻辑搬进插件之后，
  那些"看不见的等待"需要留一条线索。
- **测速与超时**：站点级超时；连续失败的站点跳过一段时间、到期自动再试
  （沿用现有那套口径），勾选不受影响。

## 十三、参考：LuCI 插件怎么注册它的 web UI

OpenWrt 的 LuCI 插件（`luci-app-*`）是同类做法，可借鉴（来源：LuCI 仓库 `applications/luci-app-example`）。

| 路径 | 作用 |
|---|---|
| `/usr/share/luci/menu.d/luci-app-xxx.json` | **菜单声明** |
| `/usr/share/rpcd/acl.d/luci-app-xxx.json` | **权限声明**（能调哪些接口；不对就 "Access denied"） |
| `/www/luci-static/resources/view/xxx/*.js` | **前端页面** |
| `/usr/share/rpcd/ucode/xxx.uc` | 后端 RPC |
| `/etc/uci-defaults/80_xxx` | 首次安装时创建默认配置 |

菜单声明形如：

```json
"admin/example/form": {
  "title": "Form View",
  "order": 1,
  "action": { "type": "view", "path": "example/form" }
}
```

- **设置存哪**：`/etc/config/xxx` —— **插件自己的配置文件**，schema 由插件自己定，
  LuCI 不认识这些字段。
- **卸载**：菜单是**扫 `menu.d` 目录发现**的，没有中心注册表 ⇒ 删包时文件一起没 ⇒ 菜单项自动消失。

**借鉴三点**：入口是"文件声明 + 宿主扫描"；设置由插件自己存自己管；
权限要显式声明（对应本项目的"这些页面要登录才能看"）。

## 十四、与现有实现的对应

| 现在 | 之后 |
|---|---|
| 源的包在 `sources/`、清单在 `sources.json` | `plugins/source/<id>/`，多类型统一 |
| 源跑在子进程、监听端口，面板用 HTTP 打它 | 插件跑在子进程，面板走**管道**、用**动作名**调用 |
| 猫源协议写死在面板（`core/catpaw.js` + agg 里几处 URL 拼接） | 收进**源插件**；面板只做"编辑参数 + 打分过滤" |
| TMDB 写死在面板（`core/tmdb.js` + `emby/tmdb.js`） | 收进**元数据插件**；面板按域分派 |
| `agg.json` 里一套全局站点勾选与打分参数 | **模板**（站点 + 参数）按**域**选用 |
| 详情快照（小时级，判据"全站都通"） | **线路结果缓存**（按天默认 1 天，判据"有线路就存"） |
| 每个运行中的源各有一个「配置中心」子页 | 收进**插件设置页**内部 |
| 客户端拿到的播放地址由面板解析坐标后 302 | 面板把 `ref` 转给插件、插件回地址，面板仍只 302 |
