# ADR-0041 `AnyProviderIdEquals` 支持多值：逐条试、认不出的跳过

- 状态：已采纳
- 相关：[0031](0031-metadata-by-domain.md)（前缀按注册表认域，认不出不猜）、[0008](0008-no-fabricated-data.md)（取不到就如实回失败码）

## 背景

客户端按外部 id 找条目时打的是 `Users/{UserId}/Items?...&AnyProviderIdEquals={前缀}.{编号}`。
实测日志（Rex/0.5.0）：

```
Users/ac403c7d4c8efe77f7353ddb4be128/Items → HTTP 200
  ?IncludeItemTypes=Series&...&AnyProviderIdEquals=tmdb.282326,imdb.tt32500958&Limit=50...
Items=0
AnyProviderIdEquals=tmdb.282326,imdb.tt32500958 → 空（只认「{已注册域}.{编号}」…）
```

该参数是**逗号分隔的多值**，语义是"任一条对上就算"（Emby 的 OR：把外部 id 交给服务端换算成库内 Id，
客户端手里可能同时有 tmdb 与 imdb 两种编号）。面板的判据是一条只认单值的正则：

```js
const PROVIDER_REF_RE = /^([A-Za-z][A-Za-z0-9]*)\.([A-Za-z0-9][A-Za-z0-9._-]*)$/;
```

逗号一进来就判"这不是按外部 id 查询" → 不在搜索分支 → 落到首页模块 → 回空。
客户端拿不到本面板的 Id，后续详情与播放**整条链路断在这里**。
（同一个客户端的 0.1.0 打的是单值 `{域}.{编号}`，那时是通的 —— 形状变了，判据没跟上。）

## 决定

**按 OR 语义把多值解成一张候选表，逐条试、先命中先返回**：

- 解析：取 `AnyProviderIdEquals` 的**全部出现**（`query.getAll`，同名参数重复也收），每项再按 `,` 切分；
  逐条 trim → 套原正则 → 走注册表认域 → **保序去重**，上限**8 条**。
- **认不出的候选跳过、不作废整条查询**：形状不合法、前缀不是已注册域，都只记进"跳过"清单，
  供日志点名；只要**还有一条**认得出，这条查询就成立。
- 取数：按候选顺序逐个 `lookup`，**先命中先返回**（命中一条就够，不再往下试）。
- **全部候选都取不到 → 如实回失败码**（与单候选时的口径一致，不回假的空成功）。
- **一条候选都没认出来 → 仍回空**，但日志逐条点名（`tmdb.282326,imdb.tt32500958 → 空（imdb.tt32500958（前缀 imdb 不是已注册域）；…）`），
  取代原来那句笼统的「只认「{已注册域}.{编号}」」。
- **不猜域**：不做 `imdb.` → `tmdb` 之类的别名映射。

## 理由

- **参数语义是协议层的事**：`AnyProviderIdEquals` 本来就是 OR；按单值解析等于把客户端的合法请求
  当成"没有可识别的查询参数"，回一个空成功 —— 比回失败码更难排查（客户端不报错，只是后续拿不到东西）。
- **判据只有一处**：`itemsWillReturnData()`（决定要不要校验账号）与 `getItems` 的搜索分支共用同一个函数，
  改解析与取数就两处同步，不会出现"出数据却没校验"或"校验了却回空"。

## 备选

- **把 `imdb.` 影射成 `tmdb` 域**：**不选** —— 域是插件注册的，面板并不知道哪个域手里握有 imdb 编号；
  猜错就是拿一个别的编号去上游要一条不存在的条目。认不出就跳过并点名（同 0031 口径）。
- **多候选并发打上游**：**不选** —— "第一条就命中"是最常见的情形，并发会在这种情况下白打若干次上游；
  串行最坏也只多 `候选数 - 1` 次请求。
- **不改，等客户端改**：客户端行为不由本面板决定 —— 同一客户端两个版本就换了形状，判据必须自己扛住。

## 后果

- 一条客户端请求最多带来 `候选数 - 1` 次额外上游请求（命中即停）；上限 8 条挡住"拿一长串外部 id 刷上游"。
- 前缀未注册的候选**不会被静默忽略**：命中与回空两条路都在日志里点名，排查时不必再猜。
- `Items/Latest` 与 `Items` 共用 `itemsWillReturnData`，因此它也会把多值判成"会出数据"（要 token），
  但 `Latest` 分支本身不处理该参数、仍然回空 —— **现状，本次不动**（实测客户端打的是 `Users/{UserId}/Items`）。
