# ADR-0038 面板重启：非托管运行方式下自拉起进程

- 状态：已采纳
- 相关：[0019](0019-self-update-from-release.md)（自身更新的协议与"非托管一律拒绝"的口径，本条目只修订后者） ·
  [update.js](../../server/modules/panel/update.js)（`restartRefusal` / `relaunchIfPending`） ·
  `docker/entrypoint.js`（托管方式下干活的那位监督者）

## 背景

面板上的「面板重启」（`POST /api/panel/restart`）原先与自更新共用一道门禁：只有**由容器引导脚本托管**
（`MB_SUPERVISED=1` 且代码装在数据卷 `app/` 下）才允许；非托管运行方式（直接跑源码）请求重启，
如实回一句"当前不是由容器引导脚本托管的运行方式，面板无法自行重启（请重起容器或手动重起进程）"。

这个理由在托管形态下成立 —— 重启靠的是"进程退出 → 引导脚本读 `.restart` 按 `current.json` 拉起"这条协议。
但在开发与源码部署形态下，它把用户推回了终端：重启的只是同一个版本的同一个进程，面板自己就能做到。

## 决定

**把「面板重启」与「自更新」拆开处理**：

- **自更新仍然只受托管时允许**（[0019](0019-self-update-from-release.md) 不变）——
  它要往数据卷 `app/` 里装新版本，必须有监督者按 `current.json` 拉起才有意义。
- **「面板重启」非托管时自己拉自己**：退出前 spawn 一个**脱离父进程**的副本，
  入口与启动参数从当前进程抄（`process.execPath` + `process.execArgv` + 入口文件），`cwd` 不变，
  `stdio` 沿用当前这个终端。版本不变、代码不变，只是换一个进程。
- **spawn 的时机是"监听都关掉之后"**：在 `shutdown()` 里 `server.close()` 之后、`process.exit` 之前。
  端口在 `server.close()` 那一刻放开，早一步子进程就会撞上 EADDRINUSE 起不来。
- **带文件看护的启动方式如实拒绝**：`npm run dev` / `node --watch`、nodemon 这些自己就会重起子进程，
  而自拉起的副本已经脱离父进程、与看护没有父子关系，两下叠加就是两个进程抢同一个端口。
  判据是"父进程的命令行里带 `--watch` 或 `nodemon`"（`ps -o command=`）。
- **非托管时不写 `.restart`**：那个标记只有引导脚本认，写了没人读。

## 理由

- 重启的语义是"把这个进程重起一遍"，非托管时它**不依赖外部任何东西**：副本跑同一份代码、同一个数据目录、
  同一个端口。唯一要做对的是"别抢端口"，而这由 spawn 时机解决。
- 与"如实拒绝"的口径不冲突：拒绝的理由是"没人把它拉起来"，自拉起正好补上这一环；
  补不上的那种情况（上面还有看护）仍然如实拒绝，并说清"为什么这里不必重启"。

## 备选方案

- **维持一律拒绝**：最保守，但把"重起同一个进程"这件面板自己能做的事推给了用户 ——
  开发时每次改设置都要回终端按一次 Ctrl+C。
- **无条件自拉起**：在 systemd / pm2 / 容器 `--restart=always` 这类外部监督者下就是两个进程抢端口；
  它们的存在看不出来（只有引导脚本会给子进程带上 `MB_SUPERVISED`），所以只在「面板重启」这条明路上做，
  且遇到能识别的看护（`--watch` / nodemon）就拒绝。
- **非托管时也允许自更新**（装到数据卷 `app/` 后拉起新版本）：会让"跑源码"这个运行方式悄悄漂移成
  "跑数据卷里的版本"，两种运行方式在判据、清理与备份口径上都不一样。不做。
- **退出后靠宿主的重启策略拉起**：见 [0019](0019-self-update-from-release.md) 的对比表 ——
  依赖启动时带了参数，且被手动停过的容器不会自动起。

## 后果

- 非托管运行方式下，重启后的进程**与启动它的那个终端脱钩**（`detached`，自成一个进程组）：
  终端关掉面板照常跑；但日志仍写在那个终端里（`stdio: 'inherit'`），终端没了就只剩面板的内存日志缓冲
  （`GET /api/logs`，重启即清空）。
- **外部监督者（systemd / pm2 / 容器的 restart 策略）下不要按这个按钮**：面板看不出它们的存在，
  自拉起会与它们的重启叠加。托管形态请照旧用引导脚本那一套。
- 重启本身的代价与托管形态一致：正在进行的请求会断、内存日志缓冲清空、插件进程被宿主停掉后由新进程重新拉起。
