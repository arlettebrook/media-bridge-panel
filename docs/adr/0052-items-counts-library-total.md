# ADR-0052 `Items/Counts` 的 `MovieCount` / `SeriesCount` 取首页插件申报的库总数

- 状态：已采纳
- 相关：[0051](0051-home-row-declared-total.md)（首页行可申报「库总数」，本条目复用它的同一条契约）、[0008](0008-no-fabricated-data.md)（不编数据）、[0029](0029-plugin-channel-and-actions.md)（插件契约：由插件申报能力）

## 背景

`GET /Items/Counts` 回一个 `ItemCounts`（Emby 官方 schema，14 个 int32 字段），面板此前**恒回全 0** —— 理由写在 [0051](0051-home-row-declared-total.md) 的「备选」里：**面板没有片库索引，数不出来**；而当时唯一能凑的数据源是插件行 `run` 出来的 `total`（如 `top_rated` 报 `11216`），那是**上游榜单的条数**，拿它当"库里有多少片"就是**编数据**。

0051 同时引入了另一条信息：首页插件的**行申报**（`rows`）里可以有**可选**字段 `total`，口径是「**这个库有多大**」—— 这正是"库总数"，与 `run` 的"这一榜有多少条"是两回事。它当时只喂给了 `Views` 的 `ChildCount`。

于是同一个客户端会话里出现两种口径：`Views` 的库角标能显示真数（1254030 / 233180 这种全库规模），而汇总用的 `Items/Counts` 仍是 0。

## 决定

`GET /Items/Counts` 的 **`MovieCount` / `SeriesCount` 改取同一份「首页插件申报的库总数」**（`rows` 里行申报的 `total`，见 0051），其余 12 个字段**仍回 0**。

归并口径（面板侧，`home.libraryTotals()`）：

- 按行的 `collectionType` 分类：`movies` → `MovieCount`、`tvshows` → `SeriesCount`；
- **同类型多行取最大值**，不相加 —— 每行申报的都是**整个库的规模**，多行是同一份规模的重述，相加等于重复计数；
- `mixed` 行**不参与** —— 它说不清是电影还是剧集，宁可缺、不可编（回落到 0）。

参数（`ParentId` 等）仍全忽略：这个端点回的是**实例级**总数，不分范围。

## 理由

- **口径终于一致**：`Views.ChildCount` 与 `Items/Counts` 用的是**同一条**「插件申报的库总数」契约，一个喂角标、一个喂汇总，不再一个真数一个 0。
- **没越过 ADR-0008 的线**：填进去的是**插件自愿申报的上游库规模**，不是面板自己算的、也不是拿"榜单条数"冒充的。插件不申报，字段就是 0（= 数不出来），不编。
- **复用既有契约，不加新字段**：0051 已经把 `rows.total` 定义清楚，本条目只是让**第二个消费者**（`Items/Counts`）也读它 —— 插件侧无需为该端点多写一行代码。
- **不碰 `Views`**：`ChildCount` 的三级取数（行申报 → `peekRowTotal` → 占位 1）不变；本条目只动 `Items/Counts`。

## 备选

- **维持全 0**：0051 时代的选择。但既然"库总数"已经由插件申报、且 `Views` 已在用，同一个数在汇总端点却回 0，**站不住**。**没选**（本条取代 0051「不改 `ItemCounts`」那一条）。
- **用 `run` 的 `total` 填**：那是"这一榜有多少条"，不是库规模，填了就是编数据。**没选**（与 0051 同款理由）。
- **同类型多行相加**：会把同一份库规模重复计入。**没选**。
- **把 `mixed` 行按某种比例拆到电影 / 剧集**：拆不出来，硬拆就是编。**没选**。
- **面板自己抓上游 / 建片库索引来数**：越权且代价大，且 0051 已定"面板不为此打上游"。**没选**。
- **字幕 / 其余 12 类也想办法填**：面板没有任何来源，只能回 0。**没选**。

## 后果

- 对客户端是**新可见值**：`ItemCounts.MovieCount` / `SeriesCount` 由 0 变为插件申报的库总数（命中申报时），其余字段与未申报时仍是 0。属契约变更，已在 `docs/emby-compat.md` 的契约变更记录里声明。
- **0 的语义要记住**：它表示**"数不出来"**，不是"库是空的" —— 与 0051 对 `ChildCount` 回退 1 的处理同源（那边取 1 不取 0，正因为 0 会被客户端当空库；这边没有更好的占位可选，只能回 0）。
- TMDB 侧继续沿用 0051 的 About 页抓取 + 缓存（成功 6 小时 / 失败退避 10 分钟），本条目不新增抓取。
- `docs/emby-compat.md` 里 `Items/Counts` 原「如实回空」的表述需改为「部分出数」。
