# ADR-0031 元数据按域分离：插件注册域 id，面板按前缀分派

- 状态：已采纳（**局部取代 [0010](0010-tmdb-config-in-panel.md)** 的"TMDB 配置归面板层"）
- 相关：[plugin-contract.md](../plugin-contract.md) · [0003](0003-local-title-scoring.md) · [0028](0028-plugin-system.md) · [0029](0029-plugin-channel-and-actions.md)

## 背景

现在整条 Emby 链路围绕 TMDB 坐标建：条目 Id 是 `tmdb_{id}_{tv|movie}[_s{n}][_e{m}]`，
季集结构、海报、简介、`ProviderIds`、时长都来自 TMDB；"认哪个前缀"是**硬编码**的
（`emby/tmdb.js` 的 `itemId` / `parseItemId` 是一对互逆函数）。

需求是能接**第二个元数据来源**（例如某一类内容只有它才有）。同时 TMDB 配置目前归面板层
（[0010](0010-tmdb-config-in-panel.md)），因为 emby 层与聚合层都要用它。

## 决定

1. **元数据插件注册一个域 id**，它就是条目 Id 的前缀（`tmdb`、以及将来别的）。
2. **面板按前缀分派**：`parseItemId` 那类硬编码改成查注册表。
3. **认不出的前缀 ⇒ 如实空并点名缺哪个插件**，不回退到别的域、不猜、不静默。
4. **条目 Id 的形状仍由面板统一规定**（见 [0029](0029-plugin-channel-and-actions.md)），
   插件只给"条目 id" + 剧集式 / 电影式。
5. **上游凭据随插件走**：TMDB 的 token 等配置由 tmdb 元数据插件自己管理
   （**取代** [0010](0010-tmdb-config-in-panel.md) 的"配置归面板层"）。
   面板设置里的 TMDB 卡片改为「元数据」栏下 tmdb 插件自己的设置页。
6. **元数据插件的动作与"面板实际取用的东西"一一对应**：取元数据 / 取一季分集 / 搜索 / 注册
   （+ 可选的首页内容与 webui）。字段清单见 [plugin-contract.md](../plugin-contract.md)。

## 理由

- **分派本来就已经是"前缀分发"**：`itemId` / `parseItemId` 干的就是"拼前缀 + 拆前缀"，
  改成查表是小改动，收益是"以后加来源不用动 emby 层"。
- **Id 形状不能下放**：它与客户端、进度库的键、首页插件的条目契约绑在一起。
  插件只给"条目 id"，面板拼形状，两边都不用懂对方的语法。
- **配置跟着插件走**：既然取数逻辑归插件，"怎么连上游"自然也归它；面板不必知道
  某个来源需要什么凭据。

## 备选方案

- **面板内建多来源**（不改 Id 方案，只在 emby 层里多写几个分支） —— 放弃：
  emby 层会被迫认识每个来源的接口，正是要避免的。
- **插件自己定义条目 Id 的完整形状** —— 放弃：面板得懂每个域的坐标语法；
  且客户端与进度库的键会被多个语法撕开。
- **保留 TMDB 配置在面板层** —— 放弃：那就得为"面板配置面板"与"插件自己的配置"各留一套，
  且第二个来源没地方放自己的凭据。

## 后果

- **元数据插件是找源的硬前置**：源侧搜索用**片名**，而坐标里没有片名，必须先问到元数据。
  ⇒ 某个域的元数据插件不可用，那个域的内容**搜索、详情、播放全断**（不只是"没有海报"）。
  ⇒ 元数据插件必须可靠，并且要自己缓存（见 [0032](0032-cache-two-levels.md)）。
- 各来源的"片名形态"不同（现有打分规则是按中文影视命名习惯定的）⇒
  打分参数可能需要按域调；参数跟着模板走（见 [0033](0033-template-and-domain.md)）正好满足这一点。
- 接第二个来源的收益取决于"它有没有季集结构"：没有就按**电影式**走（能力申报覆盖），
  不需要为它改契约。
