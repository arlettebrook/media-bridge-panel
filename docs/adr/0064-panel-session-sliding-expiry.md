# ADR-0064 面板会话：有效期可配且滑动过期，登录页独立、密码交给浏览器记忆

- 状态：已采纳
- 相关：[0017](0017-panel-auth-single-password.md)（本条目细化的那只门）、
  [auth.js](../../server/core/auth.js)、[0014](0014-frontend-no-build.md)

## 背景

[ADR-0017](0017-panel-auth-single-password.md) 定下的门禁是「单密码 + 签名会话，登录后 30 天内免登录」，
写死的一个固定值带来两个问题：

1. **时长不可调、且语义含糊。** 原有 30 天是**到期即失效**（到点强制退出）：一台天天在用的面板与一台
   装好就没再动的面板，看到的是同一条规则。想收紧口径（例如公用机器上要求很快重新登录）没有入口。
2. **登录只有一个盖在 SPA 上的遮罩框**，不是独立页面。它拿不到浏览器 / 密码管理器的「保存密码」——
   没有真实 `<form>`、没有命名输入框，用户每次都得手敲。

## 决定

1. **有效期可配、落面板设置。** 新设 `panel.sessionMinutes`（分钟，默认 **15**、上限 **43200/**30 天），
   在「面板设置 → 安全」页按「数值 + 单位（分钟 / 小时 / 天）」填写。后端 `core/auth.js` 的
   `sessionMinutes()` 读它，越界 / 读不到一律退回默认 15（不让坏值把时长搞成 0 或无限）。
2. **语义改为滑动过期（空闲计时）。** 会话 token 载荷加 `iat`（签发时刻）；门禁 `guard` 在每个请求上
   判断：一旦会话已用掉有效期的 **1/4**（或旧 token 没有 `iat`），就**重签一枚并回写 `Set-Cookie`**。
   于是「一直在用」不断顺延、只有**空闲满这一时长**才失效，而不是"从登录那刻起算到点就退"。
   cookie 的 `Max-Age` 也随之取当前时长。
3. **登录改为独立页面** `/login.html`（+ `public/core/login.js`）。`public/` 静态文件本就免登录，
   登录页据此能在"未登录"状态下被拉起来；SPA 侧 `core/auth.js` 不再渲染遮罩，改为
   `gotoLogin()` 直接 `location.replace('/login.html')`，并带 `reason`（过期 / 连不上后端）与
   `redirect`（登录后跳回原处）。
4. **「记住密码」两条路并存：浏览器表单记忆 + 勾选框自建存储。** 登录页是**真实 `<form>`**（`method=post`
   `action=/api/auth/login`）配**命名输入框**（屏外固定值 `username` + `name="password"`），
   浏览器 / 密码管理器据此保存与自动填充。页上另有**「记住密码」勾选框**：勾选且登录成功时，
   把密码 **Base64 混淆**（UTF-8 编解码）后存进本机 localStorage（`mbp-login-pw`），
   下次打开登录页自动预填并保留勾选；不勾 / 取消勾选则清除这份存储。
   正常提交由 `login.js` 接管（`preventDefault` + `fetch`）以便就地报错；
   JS 未跑起来时那条原生 POST 仍可用。

## 理由

- **滑动过期更贴近"这道门在挡谁"**：它挡的是"局域网里随手打开面板的人"，而**正在用的人**没有理由被
  中途踢出。空闲才计时，既满足"放着不管就自动收口"，又不打断连续操作。
- **1/4 作为续签阈值**：太勤会每个请求都重签、无谓写 cookie；太疏又可能"还在用却到期"。取 TTL 的 1/4
  是"活跃必然顺延、且重签次数有界"的折中；旧 token 无 `iat` 时按需补签，平滑过渡。
- **设置放面板层、读写只有 auth.js 一处**：有效期是"这道门开多久"的取舍，不属任何一栏的内容偏好，
  故归 `panel` 模块设置。`guard` 每请求都要用，而 `settings.read` 每次读盘 —— 故在 auth.js 内做一份
  内存缓存，改设置时由 panel 的 `onSettingsChange` 调 `invalidateTtl()` 失效。
- **记住密码优先交给浏览器**：自建存储要落一份可还原的凭据（混淆而非加密），比让浏览器 / 密码管理器保管更差；
  而一套真实表单就能换到系统的自动填充，成本最低、也最稳。
- **独立登录页**：只有真实页面才承载得了真实的表单语义（浏览器在"这是登录表单"的判断上认的是页面与表单，
  不是 SPA 里拼出来的几个 `input`）。

## 备选

- **保留固定 30 天、不做设置项**：否决。第一条问题没有入口解决，且"到点强制退出"的语义与"正在使用的
  人"相冲突。
- **到期即失效（不滑动）**：否决。会把"一直在用"的人也踢出去，与门禁目的（挡随手打开的人）不符。
- **自建「记住密码」（localStorage / 落盘凭据 + 自动回填）**：最初否决，**后按使用方要求采纳为可选勾选项**。
  凭据落到前端可读处，安全性低于浏览器的密码管理 —— 这是已知代价：存储只做了 **Base64 混淆**
  （不是加密，防随手翻看、防不了懂行的人），故做成勾选框、默认不勾，
  用不用由设备信任程度决定；与浏览器表单记忆并存，不取代它。
- **登录页仍做成 SPA 遮罩**：否决。拿不到浏览器的保存密码；且登录态相关逻辑与业务 SPA 混在一页。
- **每个请求都重签 cookie**：否决。写放大无谓，且 `Set-Cookie` 频繁也会干扰其它端点的响应。

## 后果

- 面板会话的对外形状变化：cookie 载荷多一个 `iat`；`Max-Age` 随设置走。签名口径不变，
  旧 cookie（无 `iat`）仍可用，并在首个请求被顺带续签为带 `iat` 的新 cookie。
- `panel` 设置新增 `sessionMinutes`（进设置备份的导出面，属正常：它本就是面板设置）。
- 「安全」页多一张「登录态有效期」卡；用户可把时长从"15 分钟"一路放到"30 天"。
- 登录入口由遮罩变为独立页：`core/auth.js` 不再导出 `renderLogin`，改导出 `gotoLogin` / `onUnauthorized`；
  未登录访问面板会跳 `/login.html`，登录后跳回原地址。
- 后续若要再调"门开多久"，**只改这一处设置与 `core/auth.js`**，前端不重复实现时长口径。
