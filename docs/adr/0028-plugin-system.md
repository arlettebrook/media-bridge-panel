# ADR-0028 插件体系：包安装、不沙箱、每个插件一个常驻子进程

- 状态：已采纳
- 相关：[plugin-contract.md](../plugin-contract.md) · [0029](0029-plugin-channel-and-actions.md) · [0015](0015-source-bundle-integrity.md) · [0019](0019-self-update-from-release.md)

## 背景

需要一套"可安装、可卸载"的插件机制，让元数据来源、源、首页内容都能以插件形式扩展。
讨论中定下了三条硬要求：**所有插件形态一致**、**"面板停插件就停"**、**复杂度尽量低**。

执行位置讨论过三档：面板进程内、一个共享的插件宿主机进程、每个插件一个子进程。
插件是否沙箱也讨论过两轮（含"分类保留：首页插件留沙箱，其余不沙箱"）。

## 决定

1. **插件按类型分组**，身份 = `(类型, 插件 id)`；类型有 `metadata`、`source`、`home`。
   目录 `plugins/<类型>/<插件 id>/`（包本体）与 `plugins/<类型>/<插件 id>/data/`（插件自己的数据）。
2. **包安装**：一个 `tar.gz`；校验复用现有的两道 md5；清单声明 `version` 与依赖，缺依赖如实失败并点名。
3. **不沙箱**：插件能读写自己的目录、能联网、能起进程。
4. **每个插件一个常驻子进程**，由面板启动与停止。
5. **"面板停、插件就停"由宿主保证**：子进程属于面板，面板退出时直接终止它们，不依赖插件配合。
   插件自己再起的东西（例如源插件内部部署的实例）必须自行清理。
6. **不硬设"同时启用插件数"上限**，但概览页要显示每个插件进程的内存占用。
7. 装插件时要**加一道确认**，明确提示"这个插件能读写数据、能联网、能起进程"。

## 理由

- **沙箱与"逻辑归插件"存在根本张力**：沙箱禁止插件联网，所有上游请求就得由宿主代做 ——
  宿主于是必须懂"怎么请求上游"，而"怎么请求上游"正是要搬进插件的逻辑。
  这一条把"分类保留沙箱"那一档否掉了。
- **同进程会把面板与 Emby 端点一起拖死**：面板进程同时服务面板页面与客户端协议，
  插件里一个同步死循环就能让两边一起卡住，且任何超时都救不回来。
- **每次执行新起一个进程贵**：一次几十毫秒（路由器更慢），而元数据是高频调用。
  要避免的是"每次新起"，不是"跨进程"—— 常驻进程之间一次调用约 0.1ms 量级，
  远小于一次上游请求的几十毫秒。
- **每个插件一个子进程**：隔离粒度合适（一个插件闹腾不影响别的插件），
  换版本只重启它自己，面板与 Emby 不受影响。
- **"面板停插件停"用宿主终止子进程实现**比"同进程 + 靠插件的 `shutdown` 钩子"可靠：
  前者不依赖插件配合。

## 备选方案

- **面板进程内（同进程）** —— 放弃：① 同步死循环无解；② 改插件要重启面板，
  "网页上传即用"消失；③ 内存泄漏只能靠容器重启复活；④ 插件可直接 `process.exit()`、
  可改全局对象，护栏无效。（已有的缓解只覆盖"抛异常"：`uncaughtException` /
  `unhandledRejection` 是"记录 + 继续跑"。）
- **一个共享的插件宿主机进程** —— 放弃：隔离粒度太粗（一个插件影响同一宿主机里的其他插件），
  且换版本要连累同宿主机上的其他插件。
- **分类保留沙箱**（首页插件留沙箱） —— 放弃：理由同上第一条；首页插件改用同一套宿主之后，
  "只判断有没有注册 webui"这类统一规则才成立。

## 后果

- ⚠️ **不沙箱的插件对面板的一切可见**：面板进程在容器内是 `root`，数据卷挂 `/data`，
  其中含 `auth.json`（面板登录凭据）、`settings/`（含上游 token）、`emby/`（客户端账号库），
  并且可以对外发送。防线因此只剩"来源可信 + 校验 + 安装确认"。
  容器本身是一层边界（**实测**：非特权、bridge 网络、只挂 `/data`），宿主路由器不在直接射程内。
- **进程数即内存**（**实测**：路由器总内存约 2.0GB、可用约 590MB；面板 `server.js` 83MB，
  两个源子进程 181MB 与 137MB；空转的 Node 进程基础开销约 40~60MB）⇒ 概览页必须能看见占用。
- 插件管理页要管 N 个进程（启停、健康、日志、崩溃重启）；这层复用现有源托管的做法。
- 走管道（见 [0029](0029-plugin-channel-and-actions.md)），因此插件与面板之间**不占端口**。
