# ADR-0034 本版当作全新安装：不做数据迁移

- 状态：已采纳
- 相关：[plugin-contract.md](../plugin-contract.md) · [0021](0021-update-replaces-app-dir.md) · [0032](0032-cache-two-levels.md) · [0033](0033-template-and-domain.md)

## 背景

插件化是一次**架构级**变化：站点勾选与打分参数变成"模板"、缓存归属与有效期口径变了、
源的托管变成插件、条目 Id 的分派从硬编码变成查注册表。旧盘上的数据形态与新代码对不上。

同时这台机器的部署规模不大，迁移代码的收益有限，而"迁错"的代价不小 ——
迁出来的东西看着生效、实际对不上，是最难查的一类问题。

## 决定

**本版当作全新安装，不做任何数据迁移**：旧配置与旧数据一律不读，新代码也不为它们留兼容分支。

会因此重来的东西（**如实列出，便于知情接受**）：

| 类别 | 内容 |
|---|---|
| 配置类 | `panel.json` 里的缓存设置；`agg.json` 的站点勾选与打分参数（模板制下本来就要重配） |
| 缓存类 | `cache/` 下的详情快照与元数据缓存（本来就是可丢弃数据，见 [0011](0011-cache-split-by-consumer.md)） |
| **用户数据** | `emby/emby.db` 里的**客户端账号与观看进度** —— 客户端要重新登录，"继续观看 / 已看"清空 |
| 已安装的插件 | 已安装的源包与其部署的实例（`sources/`）要重新装 |

## 理由

- **旧形态与新形态没有可靠的映射**：站点勾选要重新组织成"模板 + 域"，而"哪些站给哪个域用"
  本来就是人判断的事，写不出可靠的自动映射。
- **部署规模小**：迁移代码要长期维护，收益却只有"省一次重新配置"。
- **与项目一贯取向一致**："未发布的兼容不留"；不留双读分支，代码才干净、排查才简单。
- **缓存本来就是可丢弃数据**（见 [0011](0011-cache-split-by-consumer.md)），重建无成本。

## 备选方案

- **写迁移代码**（把 `agg.json` 的站点与参数搬成第一套模板） —— 放弃：映射不可靠，
  且会在代码里留下一个只跑一次的永久分支。
- **只迁"站点勾选"、参数回默认** —— 放弃：半套迁移更难解释，且同样要留分支。
- **保留 `emby.db`（账号与进度）以外的全部重建** —— 这是本决定里最需要留意的一处例外：
  若决定保留账号与进度，要单独说明，因为它是**用户数据**而不是配置，
  丢了会被当成故障（"怎么要重新登录、继续观看没了"）。

## 后果

- 升级后需要手工重配：装插件、配模板、把域挂到模板上、重新登录客户端。
- 升级说明（`CHANGELOG.md` 与 Release 说明）必须把上面那张表**原样写清**，
  特别是账号与观看进度会清空 —— 这是最容易让人感到意外的一点。
- 面板里的"清空插件数据"因此可以简单实现成**删插件的数据目录**（见 [0028](0028-plugin-system.md)）。
