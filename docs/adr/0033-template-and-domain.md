# ADR-0033 模板与域：模板是配置数据文件，每个域最多一套

- 状态：已采纳
- 相关：[plugin-contract.md](../plugin-contract.md) · [0003](0003-local-title-scoring.md) · [0027](0027-extra-fetch-only-when-zero.md) · [0032](0032-cache-two-levels.md)

## 背景

现状只有**一套全局配置**：`agg.json` 里的站点勾选、顺序、超时、打分参数、线路过滤。
而实际使用中，"动漫齐的站"与"影视齐的站"不是同一批，按内容想要的分数线与线路过滤也不同 ——
只能来回勾站点。

插件化之后有了"域"（元数据来源的前缀），于是有了一个天然的归属维度：
**不同域的内容该用哪批站点、哪套参数**。

## 决定

1. **模板就是一份配置数据文件**，内容 = **选中的站点 + 打分过滤参数 + 超时与并发**
   （分数线、最多留几条、没拿到时再往下打几条、匹配到底、线路过滤；单站超时、并发数）。
   **它自己的 id 就是这套模板的身份**（随机生成、之后固定）。
2. **每个域最多一个模板**（一对一）。一个模板**可以**被多个域共用。
3. **同一个站点可以出现在多个模板里**；站点表要能看出"它被哪几套模板用了"。
4. **站点身份按"插件 + 站点 key"记**，不用端口或实例名之类会变的东西。
5. **打分与过滤的逻辑仍在面板**，参数跟着模板走。
6. **某个域没有配模板 ⇒ 如实为空**：那个域的内容搜不到，并在日志/页面上**点名**
   "域 X 还没有配模板"。**不挑兜底、不猜**（拿"第一个模板"或某套内置默认去兜，会让"没配"这件事看不见）。

## 理由

- **不同内容想用的站与参数确实不同**：这是模板存在的唯一理由。把参数一起放进模板，
  才不用为了"某个域想用不同分数线"去改全局。
- **超时与并发也按模板走**：不同域的内容落在不同站点上，合适的超时本来就不同
  （有的站取详情要数秒，有的百毫秒），一刀切必然要么掐掉好站、要么白等。
- **一个域只挂一套**：模板本身就是按需求配好的；一个域挂多套必然出现重复，
  维护时也说不清"这次到底用了哪套"。
- **站点身份用"插件 + 站点 key"**：插件 id 是稳定的 ⇒ 插件重装、换端口之后模板照样对得上
  （原先用"源实例 + 站点 key"时，实例一变整批模板就会失效）。
- **打分逻辑留在面板**：`match.js` 是"这是不是目标作品"的唯一实现（见
  [0003](0003-local-title-scoring.md)）；搬进插件会让判据分叉、同名错片重新出现。
  参数跟着模板走则让"按域调参数"成为可能 —— 各个元数据来源的片名形态并不相同。

## 备选方案

- **一个域挂多套模板，用"默认模板"或"取并集"** —— 放弃：重复且难维护，也没解决任何问题。
- **模板只放站点、参数留全局** —— 放弃：那"不同内容想用不同分数线 / 线路过滤"就实现不了。
- **站点身份用实例 uuid** —— 放弃：比"插件 + 站点 key"多一层状态，且插件重装后 uuid 也无意义。
- **模板里直接写"服务哪些域"由模板声明** —— 保留为反向的等价形态：本决定里
  "一个模板可被多个域共用"就是这个意思，方向不重要，重要的是**域到模板最多一条边**。

## 后果

- 打分参数从"全局一套"变成"每套模板一套" ⇒ 设置页要能说清这套参数属于哪套模板。
- ⚠️ 其中**只有一部分参数对一层式站点有意义**（它们不做筛选）⇒
  设置页要写清"哪些参数只对两层式站点生效"，免得出现"调了没反应"。
- `agg.json` 里原有的那套全局站点与参数**不再读**（见 [0034](0034-fresh-install-no-migration.md)）。
- **测速不跟着模板走**：**测速的结果值（站点统计）是面板级共享的一份**，
  **测速的开关与间隔在面板设置里** —— 测速是"这台机器与这条网络"的体检，与内容偏好无关。
