# ADR-0051 首页插件行可申报「库总数」，喂给客户端 `Views.ChildCount`

- 状态：已采纳（其中「不改 `ItemCounts`」一条已被 [0052](0052-items-counts-library-total.md) 取代 —— 该条把同一份「库总数」也接给了 `Items/Counts` 的 `MovieCount` / `SeriesCount`）
- 相关：[0008](0008-no-fabricated-data.md)（不编数据）、[0029](0029-plugin-channel-and-actions.md)（插件契约：走动作名、由插件申报能力）、[0031](0031-metadata-by-domain.md)

## 背景

客户端 `Views` 里每个媒体库条目都带 `ChildCount`（真机 12/12 都有，样本全是 1，客户端拿它判断空库 / 画角标）。面板此前对它的取数是**两级**：

1. 该行被客户端**点开过**一次后，插件在 `run` 响应里申报的总数留在面板内存里（`home.peekRowTotal`）；
2. 没点开过（冷启动 / 新库）→ 回退**占位值 1**。

问题在于「总条数」这条信息**只存在于 `run` 的响应里，行申报（`rows`）里没有**：插件没法在客户端点开库之前就把「这个库有多大」告诉面板。于是**每个库第一次被看到时都只能显示占位 1**，得等客户端点进去逛一圈、面板记下来，下次才显示真数。

## 决定

**在首页插件的行申报里加一个可选字段 `total`**（口径与 `run` 的 `total` 完全一致 —— 是"这个库有多大"，不是"这一页有多少条"），面板的 `ChildCount` 按三级取数：

1. **行在 `rows` 里申报的 `total`**（客户端还没点开这个库就有真数）；
2. 该行被取过内容后，面板内存里留着的插件申报总数（`peekRowTotal`）；
3. 两个都拿不到才回退**占位值 1**（取 1 不取 0：0 会被客户端当空库）。

约束：`total` 只在 `> 0` 时被采用；插件**取不到就不写这个字段**（别写 `0`）。面板不为这个数打上游。

TMDB 首页插件用**最简路径**落这个字段：抓 TMDB 官网 About 页的 Stats（`https://www.themoviedb.org/about`），按行的 `collectionType` 映射 —— `movies` → 电影数、`tvshows` → 剧集数、`mixed` → 两者之和。抓取带缓存（成功 6 小时 / 失败退避 10 分钟），`rows` 只同步读缓存在后台刷新，**不阻塞面板每 5 秒一次的 `rows` 轮询**。

## 理由

- **客户端未点开库也能看到真数**：`ChildCount` 从"逛过才有"变成"申报就有"，首页角标、空库判断立刻准确。
- **不为库总数打上游**：`rows` 是高频端点，面板的做法是**插件自愿申报**、面板只读插件给的值 —— 面板自己不去抓 About；抓取与缓存都是插件自己的事，且被踢到后台。
- **守住 ADR-0008 的边界**：库总数是**插件自愿申报的上游库规模**，不是服务端 `ItemCounts`，也不是面板自己编出来的数。插件拿不准就**不申报**（面板回退占位 1），而不是填一个好看的数字。
- **与既有 `ItemCounts` 的口径不冲突**：`GET /Items/Counts` 当时恒回全 0（那是"面板数不出服务端片库"）。这里给的是**库级** `ChildCount`，二者各管各的。（后续 [0052](0052-items-counts-library-total.md) 推翻了这一条：既然 `total` 就是"库有多大"，同一个数让汇总端点回 0 站不住，遂把 `MovieCount` / `SeriesCount` 也接给它。）

## 备选

- **面板自己抓 TMDB About / 读 `discover.total_results`**：前者把上游依赖塞进面板、与插件体系解耦的取向冲突；后者无筛选时 `total_results` 被钳在 20001，**不是全库数**。**都没选** —— 抓取是插件的事，面板只消费申报值。
- **不申报，保持占位 1**：改动最小，但库角标永远不准；有能力的插件白白浪费已知信息。**没选**。
- **用 `run` 的 `total` 当库总数**：`run` 的 `total` 是"这一页 / 这一行榜单的条数"，与"上游库有多大"是两回事，硬拿来当库规模会误导客户端。**没选** —— 契约里把这两件事分开写。
- **让 `ChildCount` 直接回真机那样恒 1**：那是真机样本的巧合（12 个库都是 1），不是协议语义；客户端本就拿它判断空库，恒 1 会让所有库看起来都非空且都只有 1 条。**没选**。
- **改 `ItemCounts` 回真数**：越权 —— 那是服务端级计数，且面板没有片库索引，回真数就是编。**没选**（既有决策、不复刻真机）。（注：0052 只把**插件申报的库总数**填进 `MovieCount` / `SeriesCount`，**不是**"回真数"—— 那仍是插件自愿申报的上游库规模，与"面板凭空数出片库"不同。）

## 后果

- 客户端在**还没点开库**时就能看到库里真实条目数（命中申报时）；未申报 / 取不到的库仍显示占位 1。
- 对客户端是**新可见值**（`ChildCount` 命中行申报时不再是 1）—— 属契约变更，已在 `docs/emby-compat.md` 的契约变更记录里声明。
- 插件侧多一个可选字段与一份缓存策略；拿不准的插件不受影响（字段可缺，行为回退到旧口径）。
- TMDB 的 About 抓取多了「冷启动第一次短暂回退占位 1、几秒后自愈」「上游改版导致解析失效则不申报」两个已知退化点 —— 都收敛到"回退占位"，不会编数。
