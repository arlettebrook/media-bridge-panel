# ADR-0035 插件不随面板发行，改从独立的插件仓库安装

- 状态：已采纳
- 相关：[plugin-contract.md](../plugin-contract.md) · [0028](0028-plugin-system.md) · [0034](0034-fresh-install-no-migration.md) · [0015](0015-source-bundle-integrity.md)

## 背景

插件体系落地时留了一个"随包发行"的口子：面板仓库里 `plugins/<类型>/<id>/` 放插件源码，
面板开机把这份源码按**内容指纹**同步进数据目录（指纹一致就跳过，首次同步即启用）。

这个口子带来一个说不通的后果 —— **卸载不生效**。实测：装好并启用一个源插件后，
在管理页卸载它（`DELETE` 返回 200、目录也确实删了），**重启面板之后它又回来了** ——
`syncBuiltins()` 把仓库里那份源码重新同步进数据目录、并起进程。用户视角是"卸载按钮坏了"。

更根本的矛盾在于：**"随包发行"本就不成立**。发布流程（`.github/workflows/release.yml`）
只打 `server.js` / `server` / `public` / `package.json` / `README.md`，**没有 `plugins/`**；
真正的 Release 安装天然是零插件。开发机上"装完就带着一堆插件"，只是因为运行目录是**整仓手拷**。

## 决定

**去掉"随包发行"这个概念，插件一律从面板之外来。**

- 面板的 Release 包里**没有插件**，装完是**零插件**。
- 删除后端的 `builtinRoot()` / `listBuiltins()` / `syncBuiltins()`三个函数与它们的开机调用 ——
  卸载就是卸载，重启不再装回来。
- 插件源码仍然留在面板仓库的 `plugins/` 下（开发用），但**只作为构建插件的输入**：
  由 `tools/plugin-pack.js` 打成 `tar.gz`（打包时给包内 `plugin.json` 注入 `files` 逐文件 md5），
  连同清单 `index.json` 推进**独立的插件仓库** `dlushu/media-bridge-plugins`。
- 面板新增**插件库**：从该仓库（`PLUGIN_REPO` 可换）直取清单与包安装；仓库里**只收产物，不收源码**。
- 归口两条安装路径，只差来源标记：

  | 入口 | 包从哪来 | `origin` |
  |---|---|---|
  | 「插件库」页（`/api/plugins/library`、`/api/plugins/library/install`） | 插件仓库 | `library` |
  | 「管理」页手动上传（`/api/plugins/install`） | 本地上传的 `.tar.gz` | `manual` |

  两者共用同一套解包与两道 md5 校验（[0015](0015-source-bundle-integrity.md)），
  落进同一份数据布局 `plugins/<类型>/<id>/`。

## 理由

- **修掉一个真 bug，而不是给它加补丁**：与其在卸载时"记住别同步回来"，不如去掉同步本身 ——
  根因是那份"内置清单"，不是卸载逻辑。
- **让"装了什么"只由本机的数据目录说了算**：面板不再有一份"本应存在"的隐性清单，
  排查时不必再区分"是没装"还是"被装回来了"。
- **薄的面板、厚的外部产物**：面板仓库只发面板；插件按自己的节奏独立发布，
  改一个插件不必连带发面板。这与 [0034](0034-fresh-install-no-migration.md)"本版全新安装、不留兼容"的取向一致。
- **两道校验终于有意义**：手写的 `plugin.json` 里没有任何插件声明 `files`，第二道校验形同虚设；
  改由打包器**自动注入逐文件 md5**，包一旦被改动就装不上、并点名到文件。

## 备选方案

- **卸载时记一份"用户主动卸载过"的名单，开机同步时跳过** —— 放弃：把"卸载"变成"隐藏"，
  数据目录与隐式清单两处状态要长期对齐，正是最容易出错的一类设计。
- **把插件包直接提交在面板仓库里、开机从包安装** —— 放弃：面板仓库会同时装源码与产物两份，
  仍然没解决"面板自带插件"的定位问题。
- **插件仓库同时放源码** —— 放弃：源码需要构建步骤与仓库间同步，而面板仓库已经承担了源码；
  插件仓库只收产物，边界最清楚。
- **插件自动更新**（面板定时比对清单版本、静默升级） —— 本版不做：更新插件会重启进程、
  可能换掉正在用的行为，属于要显式确认的动作。清单里标出 `hasUpdate` 供人工判断即可。

## 后果

- 全新安装后**没有元数据也没有源**：要先到「插件库」装一个元数据插件（如 `metadata/tmdb`）
  与需要的源插件，才会出内容。README 的「第一次使用」必须把这一步写在最前面。
- 插件仓库成为**发行链路上的一个新环节**：面板拉不到清单时「插件库」页如实报错并给出原因，
  但已装的插件照常运行（库不可用不影响本机已有的插件）。
- 插件仓库的包与 `index.json` 是**产物**，不进面板仓库的版本控制；
  面板仓库侧新增 `tools/plugin-pack.js` 作为唯一的产出方式。
- 历史条目里的 `origin` 可能写着 `builtin` / `upload`：按同一口径**归并显示**
  （`builtin` → 插件库、`upload` → 手动安装），不做数据迁移（[0034](0034-fresh-install-no-migration.md)）。
