# ADR-0036 图片端点一律 302：面板不再代取字节

- 状态：已采纳
- 相关：[0013](0013-image-endpoint-signing.md) · [0006](0006-redirect-for-playback.md) · [emby-compat.md](../emby-compat.md)

## 背景

图片端点（`Items/{Id}/Images/{type}`）此前**由面板把图取回来再转发**，理由有两条：图很小；
插件给的图地址可能是客户端根本连不到的地方。

它与播放的取向不一致：播放早已定为**一律 302**（[0006](0006-redirect-for-playback.md)），
面板不扛流量；图片却一直占着面板的带宽与一条出网路径，并附带"单张 8MB 上限""取图失败 → 502"
两条只为转发而存在的分支。

## 决定

- 图片端点**一律 302**：只回 `Location`，取值是 tag 或本地索引里的图片 URL，字节在源站与客户端之间直接跑。
- 面板不再代取字节，随之删除单张 8MB 上限与"取图失败 → 502"两条分支。
- tag 验签与本地索引**保持不变** —— 端点仍豁免 token，这两条仍是唯一的 SSRF 防线（见 0013）。

## 理由

- 与播放同一条取向：面板只做"把地址交出去"的事，不扛流量、不代取字节。
- 免去面板对图床可达性的依赖 —— 面板与客户端可能处在不同网络，由面板代取本身就不构成保证。

## 备选方案

- **维持面板代取**：能兜住"客户端连不到图床"这种情况，代价是面板扛下全部图片流量，
  并要长期维护上限、超时与 502 语义。已放弃 —— 取舍回到 0006 那条线上。
- **把图片直链编进 DTO 交给客户端自己加载**：协议里没有这条路。`BaseItemDto` 没有任何图片直链字段
  （见 0013 与 emby-compat.md），客户端一律自己拼 `Items/{Id}/Images/{type}?tag=…`。

## 后果

- 图片字节不再经过面板：面板侧图片带宽归零，也不再产生"取图失败 → 502"。
- **客户端必须自己连得到图床**：图床不可达时图片整体失败，面板不再兜底。
- 图床若对来源有要求（`Referer` / `User-Agent` 等），由客户端自己的请求承担，面板不再替它补齐。
- 缓存语义不变：`Location` 响应仍带 `Cache-Control: max-age=86400`。
