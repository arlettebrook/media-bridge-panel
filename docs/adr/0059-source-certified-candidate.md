# ADR-0059 片源认证：候选行上的 `vod_exact`，面板见到直接记 1、不再判名字

- 状态：已采纳
- 相关：[0003](0003-local-title-scoring.md)（本地打分，不做反查）·
  [0033](0033-template-and-domain.md)（打分与过滤留在面板）·
  [0008](0008-no-fabricated-data.md)（不编数据）·
  [match.js](../../server/modules/agg/match.js)（`scoreItem` 短路处）·
  [service.js](../../server/modules/agg/service.js)（条目原样进打分）·
  插件仓库 `docs/plugin-contract.md` 第五节「候选行上的认证标」

## 背景

聚合层判「这条是不是目标作品」**只有一套判据**：`match.js` 的三项加权打分
（名字 0.7 · 季集 0.2 · 年份 0.1），外加两道闸门（名字硬拒 / 分数线）。
它把名字相似度当成通用信号 —— 对「斗破苍穹」这类中文片名是对的，对**番号片**却会失手：

- 番号查询时，目标往往是短短七个字符（`SSIS-001` / `MD0338`），而源给的候选是
  三四十字的日文 / 中文**完整标题**。相似度被长标题稀释，**实测 24 条正确候选里 23 条
  被判「相似度过低」出局**。`match.js` 里为此开了一条**番号通道**（两侧抽得出同一番号 → 名字分 1.0），
  但那条通道靠正则抽号，要求「字母 + 分隔符 + 数字」的形态。

- 更关键的是**信息不对称**：一个番号站点的 `search` 常常**已经按番号精确过滤过**了
  （搜索词本身就是番号，它把候选筛到只剩同一番号那一条）——「这一条就是目标」这个事实，
  **站点自己知道得最清楚**，面板却看不见，只能就着标题重新猜一遍。
  面板不认识各站的过滤逻辑，也不该去认识（站点协议千差万别）。

于是出现一种尴尬：**插件的确定性判断，被面板的通用判据覆盖掉了**，把正确的结果拒之门外。

## 决定

**在候选行（macCMS 形状）上加一个可选的布尔字段 `vod_exact`：插件认准「这条就是目标作品」时写 `true`，
面板 `scoreItem` 见到 `vod_exact === true` 就短路 —— 直接给分数 1，不再判名字。**

- **字段层级 = 候选行**（`search` 回来的 `json.list[]` 里那一条），与 `vod_id` / `vod_name` /
  `vod_pic` / `vod_remarks` 同命名空间。
- **缺省不认证**：不写 / 非 `true` = 面板照旧走它那套打分，一行不改。
- **面板怎么采信**：`match.js` 的 `scoreItem` **最前**短路
  （`if (item && item.vod_exact === true) return { score: 1, rejected: false, reason: '片源认证（插件认准，直接采信）', parts: {}, signals: null }`）。
- **其余一切不变**：认证项仍照常受**分数线**（`matchMinScore`）与 **`maxItems`** 约束；
  只因分数为 1，它会排在最前、**优先被取详情**（也优先进入接续补打的名单）。
- **只对两层式站点有意义**：认证标长在候选行上，一层式站点（`search` 直接回播放项）不经过
  `search → 判分` 这条路。
- **契约写在插件仓库**（`docs/plugin-contract.md` 第五节）：面板是消费方，不在本仓库改契约、
  也不留副本（见 [AGENTS](../../AGENTS.md)）。

## 理由

- **这是插件的「声明性标注」，不是把判据搬进插件**（与 [0033](0033-template-and-domain.md) 相容）：
  `vod_exact` 只在**这一条候选**上生效，面板仍是「这是不是目标作品」的**唯一判据实现**
  （`match.js`），也仍对没有认证标的候选照常打分。判据**没有分叉** —— 插件只是把
  「这一条已确定」这个**只有插件自己才知道的事实**如实标注出来，判据怎么用仍由面板定。
  （同 [0042](0042-auth-line-byte-relay.md) 的 `playVia`：插件声明、面板执行。）
- **把确定性还给最知道的人**：番号站按番号精确过滤后的候选，命中与否**站点自己最有把握**，
  比面板从标题反推更准。让插件标注、面板采信，是信息流向的自然方向。
- **不扩大面板的番号正则**：另一条路是让 `match.js` 的 `CODE_RE` 更宽容（允许 `MD0338` 无横杠），
  但那会把 `x264` / `hevc265` 这类编码串误当番号（`match.js` 刻意要求分隔符正为此）。
  认证标把这件事交给**知道语境的插件**，面板正则不必冒险放宽。

## 备选

- **面板自己认更多番号形态（放宽 `CODE_RE`）**：看似零契约改动，代价是编码串误判（`x264` → 番号），
  且**站点各自不同的过滤口径**面板无从得知。**否**。
- **插件直接把候选改写成面板会认的名字**：等于插件**编数据**（[0008](0008-no-fabricated-data.md)），
  且改写后的名字仍可能被面板闸门再拒一次。**否**。
- **插件自己挑最终结果、只回一条**：判据分叉，违背 [0033](0033-template-and-domain.md)
  （「这是不是目标作品」应只有一处实现）。**否**。
- **让认证项豁免分数线 / `maxItems`**：把「信任」放大成「免检」，会绕过面板的取详情限流
  （每条命中都要打一次站源 `/detail`，不限就是十几秒）。**否**，认证只改分数，不改流转。

## 后果

- **认证项不再参与名字 / 季集 / 年份打分，`parts` 为空、`signals` 为 `null`**：
  线上诊断里这条的「为什么这个分」只有一句「片源认证」。这是有意的 —— 认证的含义就是
  「不用解释，已确定」。
- **单集压制对认证项失效**：`episodeScore` 不再作用于它（`signals` 空）。既然站点已认准整条，
  就不再用面板的集号信号去压。属**已接受**的取舍。
- **标错 = 误认，没有名字兜底**：插件标了 `vod_exact` 而实际不是目标，面板**不会**用名字拦它。
  责任在插件 —— 契约里明确写了「拿不准就别标」，且只在**确定性把握**时使用。
- **认证不保证能播**：分数只影响「进不进版本列表」与排序，能不能取出线路仍要过 `/detail`；
  与既有语义一致。
- **契约同步面**：字段定义在插件仓库 `docs/plugin-contract.md` 与 `docs/source-display-rules.md`；
  本仓库改 [emby-compat.md](../emby-compat.md)（含「契约变更记录」）、[CHANGELOG.md](../../CHANGELOG.md)
  与本条 ADR。**missav 片源**先行适配：番号精确过滤后的候选带 `vod_exact`。
