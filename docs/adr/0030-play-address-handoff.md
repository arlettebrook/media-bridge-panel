# ADR-0030 播放地址的转交：伪地址的 host 是面板，`ref` 由插件解析

- 状态：已采纳
- 相关：[plugin-contract.md](../plugin-contract.md) · [0006](0006-redirect-for-playback.md) · [0029](0029-plugin-channel-and-actions.md) · [0032](0032-cache-two-levels.md)

## 背景

现状：客户端拿到的播放地址是**面板的地址**（`…/api/emby/Items/{id}/Stream?MediaSourceId=…`），
点播放时**面板**解析 `MediaSourceId` 里那段 base64（源 / 站点 / 线路 / 地址），然后 **302** 到真实地址。

插件化之后，"这条坐标对应哪个真实地址"只有插件知道。同时遇到一个现实问题：
把播放地址直接查出来放进详情，会**带时效**（很多直链含 token / 过期时间），
而线路结果是会被缓存的。

## 决定

1. 播放项里给客户端的地址是**面板的地址**（形如 `http://<面板域名>:<面板端口>/…/<ref>`）。
   面板收到请求后通过管道把 `ref` 转给插件，插件回一个**真实可直连地址**，面板 **302** 过去。
2. **host 必须是面板**，不能是插件自己开的端口。
3. **只做 302**：插件给不出"客户端可直连的地址"（例如必须带 header / cookie）时，
   面板**如实回"该源需要代理，暂不支持"**，不静默失败。
4. **`ref` 由插件输出、插件自己管**：只要内容还在，插件随时能把它换成一个地址 ——
   **可重复解析是插件的义务**；地址缓存与有效期也由插件自己处理。因此线路结果可以照常缓存。
5. **播放项必须带一个显示名**（聚合站给线路名，直查那类自己决定：片名 / 集号 / 站点名都行）。
   **面板只负责把它传到客户端 —— 不起名、不编**；插件想不出名字就如实留空。

## 理由

- **客户端要能访问那个地址**：面板的端口是已发布、确定可达的；插件自己的端口没有发布
  （现状里"源端口没发布"就导致过配置中心打不开）。客户端因此感知不到插件，也不需要知道插件在哪。
- **等于把现有链路里的"解析坐标"那一步从面板挪进插件**，链路形状不变、[0006](0006-redirect-for-playback.md)
  的取舍（面板不扛流量）也不变。
- **"伪地址 + 插件解析"同时解决了时效问题**：给出去的是稳定地址，面板可以照常缓存线路结果；
  真地址在**点播放那一刻**由插件现取。
- **名字由站点给**而不是面板起：名字是站点的信息（现有实现里 `Name` 是
  `${站点标签} · ${线路名}`，线路名来自源）。面板起名会碰上"不编数据"的边界；
  让站点给，既如实又不越界。

## 备选方案

- **面板破例做代理** —— 放弃：推翻 [0006](0006-redirect-for-playback.md)，面板从此要扛流量
  （带宽、超时、断点续传都要管）。
- **插件自己代理**（插件把地址给回来，由它自己转发） —— 放弃：那个端口要能被客户端访问，
  等于每个这类插件都得自行发布端口，路由器上多一串暴露面。
- **详情里直接给真直链** —— 放弃：直链常带时效，缓存住它会让"点开就是过期地址"；
  而不缓存则要把整份详情交给插件，得不偿失。
- **面板在只有一个播放项时起一个默认版本名** —— 放弃：见决定第 5 条。

## 后果

- **播放多了一跳**（客户端 → 面板 → 插件解析 → 302）。管道那次往返可忽略（亚毫秒级），
  但**如果插件的解析要现场访问上游（秒级），客户端点播放就要等那么久** ⇒
  这是插件的实现义务（内部缓存或预热），面板帮不了。
- **需要代理的内容第一版不支持**，界面上要如实说明，不能静默失败。
- `ref` 的可重复解析是**插件的义务**。不写清楚的话，出事时归因不明
  （是插件没做到，还是面板不该缓存）。
