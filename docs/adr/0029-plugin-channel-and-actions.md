# ADR-0029 插件契约：走管道、用动作名、由插件申报能力

- 状态：已采纳
- 相关：[plugin-contract.md](../plugin-contract.md) · [0028](0028-plugin-system.md) · [0030](0030-play-address-handoff.md) · [emby-home-plugin.md](../emby-home-plugin.md)

## 背景

现有的"源"是"一个包 + 一个进程 + 一个端口"，面板用 HTTP 打它的 `/config`、`/search`、
`/detail`、`/play`。协议细节写死在面板两处：`core/catpaw.js` 的导出，以及聚合层里几处 URL 拼接。

要把这一套变成通用插件契约，需要定三件事：**面板与插件怎么通话**、**端点怎么命名**、
**插件要申报什么**。另外"归一化"与"条目 Id 的编解码"归属也要定。

## 决定

1. **走管道**：面板启动插件时接一条通道（Node 的 child IPC；非 Node 插件可用
   "stdin/stdout 每行一条 JSON"）。不占端口、不用鉴权（只有父子能碰）、更快。
2. **动作名**：端点名是**语义动作标识**（`站点清单` / `搜索` / `取播放项` / `解析地址` / …），
   不写成 `/config`、`/search` 这类路径样式 —— 免得后来者以为还要发 HTTP。
3. **插件内部要不要给自己的实例开端口，是插件自己的事**：面板不参与分配、也不依赖它。
4. **能力申报**：
   - 源插件：**站点级**申报（有哪些站点、每个站点的能力；站点数可以是 0）。
   - 元数据插件：**注册**时申报"它会哪些字段、缺哪些" + 是**剧集式**还是**电影式**。
5. **归一化归插件**：面板规定"要哪些字段"，插件按规范归一后返回；面板只把规范字段转成 Emby DTO。
6. **条目 Id 的形状由面板统一规定**，插件只提供"条目 id"（它自己的编号）+ 剧集式 / 电影式声明。
   坐标的编解码不下放给插件。
7. **打分与过滤留在面板**，不搬进插件。
8. **失败如实**：插件报失败，面板如实记日志、如实空；不编造、不静默回退。
   插件返回里可带**可选诊断字段**（如"这次含预热""内部等了多久"），面板照实写日志、不参与打分。

## 理由

- **管道是这个项目已有的做法**：首页插件就是这么跑的（`job` / `rpc` / `rpcResult` / `done`），
  超时、错误回报、日志都在 ⇒ 选它等于复用现成的一套；选端口则要新造"端口分配 + 冲突处理 + 残留清理"。
- **端口是紧俏资源**，而这台机器上端口要留给真正的服务；插件数量还会涨。
- **归一化归插件**才真的让"逻辑归插件"成立：现在聚合层里那套"从播放列表定位到第几集"的解析
  （源里那种 `[842.5MB]211 4K.mp4`）本来就是猫爪的知识，却写在聚合层里。
- **条目 Id 的形状必须由面板统一**：它与客户端、进度库的键、首页插件的条目契约绑在一起，
  不能每个域一套语法。
- **打分判据必须统一**：`match.js` 是"这是不是目标作品"的唯一实现。搬进插件会让判据分叉，
  同名错片会重新出现；而且它还牵着一串只属于面板的概念（分数线、留几条、补打 K、线路过滤）。
- **诊断字段**是因为 `init` 这类内部逻辑搬进插件之后，"看不见的等待"就没有线索了。

## 备选方案

- **本地端口 + HTTP**（现状"源"的形态） —— 放弃：需要端口分配与冲突处理。
  它唯一真实的好处是调试直观（`curl` 就能打），用"面板把每次请求与回复写进日志"覆盖。
- **Unix socket** —— 放弃：不占端口号、可 `curl --unix-socket`，但要管路径与残留文件。
- **归一化留在面板**（现状） —— 放弃：面板就得懂每个插件的数据形状，与"逻辑归插件"相抵。
- **坐标编解码下放给插件** —— 放弃：面板将不得不懂每个域的坐标语法。

## 后果

- 调试不如 `curl` 直观 ⇒ 面板把每次请求与回复写进日志（沿用现有源"留子进程尾部日志"的做法）。
- 插件的上游请求由插件自己发（面板不再代做），所以面板侧不再需要"通用转发"那套能力。
- **元数据插件是找源的硬前置**：源侧搜索用的是**片名**，而条目坐标里没有片名 ——
  必须先问到元数据才能去搜源。因此**元数据插件不可用，那个域的内容整条链都不可用**
  （不只是"没有海报"）。各元数据的"片名形态"不同 ⇒ 打分参数可能需要按域调（参数跟着模板走，
  见 [0033](0033-template-and-domain.md)）。
- 认不出的前缀一律**如实空并点名缺哪个插件**（不回退到别的域）—— 与现状
  "认不出的前缀点进去没资源"一致。
