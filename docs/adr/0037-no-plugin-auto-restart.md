# ADR-0037 插件进程崩了不自动重启

- 状态：已采纳
- 相关：[0028](0028-plugin-system.md) · [0016](0016-source-auto-update-default-off.md) · [plugin-contract.md](../plugin-contract.md)

## 背景

插件宿主（`server/modules/plugin/host.js`）原先在插件进程**自己退出**时按退避策略自动重启：
只有"启用中"的插件才重启，最多 5 次 / 5 分钟，每次都在面板日志里点名（[0028](0028-plugin-system.md) 的"看护"一条）。

## 决定

- 进程自己退出**只如实记账**：状态转 `stopped`、退出码写进 `lastError` 并进面板日志。
- **不再自动重启**：想让它继续跑就回「插件 → 管理」页点「启动」。
- 「重启」按钮与 `POST /api/plugins/:type/:id/restart` **保持不变** —— 那是人在按，不是看护；
  源自动更新触发的重启（[0016](0016-source-auto-update-default-off.md)）同理。
- 状态里不再有"重启次数"字段（它只服务于自动重启）。

## 理由

- 崩溃多半出在插件自身：配置填错、上游挂了、代码有 bug。自动重启会把"一直崩"变成"一直在重启"——
  日志被刷屏，真正的原因反而被盖住，还可能在启动中途反复抢端口。
- 坏在哪看得见，比"救活"更重要：这条口径与"不编数据"（[0008](0008-no-fabricated-data.md)）同源。

## 备选方案

- **维持退避重启**：能兜住偶发崩溃。已放弃 —— 偶发崩溃重启一次也救不回来（下次搜索照崩），
  而反复重启带来的日志噪声与端口抢占是实打实的代价。
- **崩溃后自动把插件置为"停用"**：比自动重启更彻底，但把"进程状态"与"启用开关"两件事搅在一起，
  用户会分不清是自己关的还是系统关的。不做。

## 后果

- 插件崩了就停在那儿：管理页显示为「已启用（没在跑）」，`lastError` 记着退出码，日志里有那一行。
- **没有自愈**：无人值守时，崩掉的插件会一直缺席，直到有人去点「启动」。
- 退避参数（`RESTART_MAX` / `RESTART_WINDOW_MS`）与 `restarts` 计数一并移除。
